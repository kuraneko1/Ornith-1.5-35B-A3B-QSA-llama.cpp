# Tesla V100 notes (measured configuration)

This is the only configuration measured so far. Treat it as a reference, not as a
requirement: build the engine for your own GPU and toolkit.

## Hardware

| item | value |
|---|---|
| GPUs | Tesla V100-PCIE-32GB + Tesla PG500-216 32GB (2 × 32 GB, sm70) |
| CUDA | 12.9 |
| OS driver | 580.178.04 |
| Model | `Ornith-1.5-35B-Q8_0-QSA-mm1.gguf` (Q8_0, FP32 indexers) |
| KV | F16 |
| Context | 262,144 |
| VRAM at 262k | 23,242 + 20,872 MiB / 32,768 ×2 |

## Build

```sh
cmake -B build-cuda12 -G Ninja -DCMAKE_BUILD_TYPE=Release -DGGML_CUDA=ON \
  -DCMAKE_CUDA_ARCHITECTURES="70;86" \
  -DCMAKE_CUDA_COMPILER=/usr/local/cuda-12.9/bin/nvcc \
  -DLLAMA_CURL=OFF -DBUILD_SHARED_LIBS=ON -DGGML_NATIVE=ON
cmake --build build-cuda12 -j8 --target llama-server
```

`86` is kept for a second card that may be present; it is not needed on a V100-only box.
V100 has no Turing MMA, so the indexer uses the vector kernel and the QSA attention uses
the F16 path of `qsa-attn.cu`.

## Run

```sh
LLAMA_QSA_SPARSE=1 LLAMA_QSA_IDXDIRECT=1 \
  build-cuda12/bin/llama-server -m Ornith-1.5-35B-Q8_0-QSA-mm1.gguf \
  --mmproj mmproj-Ornith-1.5-35B-BF16.gguf -c 262144 -ngl 99 \
  --split-mode layer --tensor-split 1,1 --flash-attn on -ctk f16 -ctv f16 \
  --jinja --reasoning-format deepseek -a ornith-qsa
```

At 262k the KV cache plus weights leave about 19 GB free; lower `-c` if another process
shares the cards.

## Measurements

Four real tasks (2 code, 2 prose) × 2 repeats, 256 output tokens, greedy. Sparse
prefill + indexed indexer:

| context | prefill tok/s | decode tok/s |
|---:|---:|---:|
| 0 (short tasks) | 408.6 | 88.6 |
| 4,096 | 791.1 | 86.3 |
| 16,384 | 762.6 | 84.9 |
| 65,536 | 737.4 | 82.5 |
| 131,072 | 726.6 | 80.0 |
| 261,120 | 709.6 | 75.9 |

Decode at 4k falls 12% by 262k. The same model on the mask-path / gather-indexer build
measured 339.3 prefill and 68.3 decode at 261,120 tokens: **2.09× prefill, +11.2%
decode** from the sparse prefill and indexed indexer.

The 262k cold prefill takes about 369 seconds; decode is 64 tokens in about 0.8 seconds.

## Notes and limits

- Single sequence, cell == position. The sparse path is gated to that case.
- MTP stays dense. The 27B fork's MTP and block-refresh cache are not ported.
- Quality was checked with passkey needles at 8k and 16k, not with PPL or long-form QA.
- These numbers are one machine, one run per depth; they are not a guarantee.
